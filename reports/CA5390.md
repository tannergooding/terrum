# CA5390: 42 seconds on byte-array opcode writes without encryption APIs

> [!NOTE]
> Drafted with AI assistance using measured SDK analyzer timings.

### Environment

Windows x64 (10.0.26200), .NET SDK `11.0.100-rc.1.26425.128`,
MSBuild `18.11.0-1.26425.128+3551975be`. Bundled
`Microsoft.CodeAnalysis.NetAnalyzers.dll` file version `11.1.26.42628`.
Target `net11.0`, `AnalysisLevel=latest-all` (CA5390 is otherwise disabled
by default).

### Reproduction

Create a `net11.0` class-library project with `AnalysisLevel=latest-all`
and `ReportAnalyzer=true`. Use this source pattern:

```csharp
using System;
using System.Collections.Generic;

public sealed class Encoder
{
    private readonly List<byte> _bytes = new();
    private void Bytes(params byte[] values) => _bytes.AddRange(values);

    public int Emit()
    {
        Bytes(0x48, 0x89, 0xC8, 0x48, 0x89, 0xC8, 0x90, 0x90);
        // Repeat the line above at 2,048 distinct source locations in this method.
        // Do not use a runtime loop: the number of literal array creation sites matters.
        return _bytes.Count;
    }
}
```

There is **no encryption API or key-consuming sink**. Build with
`dotnet build -c Release -t:Rebuild -p:ReportAnalyzer=true -v:diag`;
normal verbosity did not show per-rule timings on this SDK. Compare
128, 512 and 2,048 literal call sites, then change only the helper
signature to `Bytes(params ReadOnlySpan<byte> values)` and rebuild.
The unrelated CA1050 warning does not prevent the build.

| Call sites | Signature | Build process wall | CA5390 analyzer | CA5403 analyzer |
|---:|---|---:|---:|---:|
| 128 | `byte[]` | 0.89 s | 0.004 s | 0.059 s |
| 512 | `byte[]` | 1.35 s | 0.024 s | 0.707 s |
| 2,048 | `byte[]` | 53.97 s | 42.179 s | 10.426 s |
| 2,048 | `ReadOnlySpan<byte>` | 1.71 s | <0.001 s | <0.001 s |

At 2,048 sites, changing only the helper's parameter type removed both
rule costs. The analyzer numbers are not wall time and can overlap. These
measurements do not by themselves reproduce the longer project-scale cost.

### Project-scale impact

A C# compiler host's Release rebuild took **23:00.29 wall time** with
**693.321 analyzer-seconds attributed to CA5390**, 1,324.598 to CA5403
and 2,220.343 to all analyzers. After changing an opcode writer from
`params byte[]` to `params ReadOnlySpan<byte>` and moving a few other byte
writes behind helpers, the rebuild took **2:10.41 wall time**; CA5390
reported 0.443 analyzer-seconds, CA5403 0.485, with both rules still
enabled. SHA-256 hashes for two representative PE outputs matched
before/after. These two larger snapshots also contain other code changes:
the self-contained test above, not their wall-time delta, isolates the
signature change.

### Expected behavior and investigation

[CA5390](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/quality-rules/ca5390)
finds hard-coded data supplied as an encryption key. Its
[constant-array source definition](https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Utilities/FlowAnalysis/FlowAnalysis/Analysis/TaintedDataAnalysis/HardcodedSymmetricAlgorithmKeysSources.cs)
recognizes arrays of 5-16, 24 or 32 bytes; the eight-byte opcode call
falls in that range, but no source ever reaches a cryptographic sink.
The [CA5390 rule implementation](https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Microsoft.CodeAnalysis.NetAnalyzers/Microsoft.NetCore.Analyzers/Security/DoNotHardCodeEncryptionKey.cs)
uses `SourceTriggeredTaintedDataAnalyzerBase`, as does CA5403.
Can source/flow work be gated or reused when the compilation has no
key-consuming API, and can this input be added as a regression test?
The exact expensive internal step is not established. The
[older joint deprecation/performance issue](https://github.com/dotnet/roslyn-analyzers/issues/6737)
describes the known issue, but does not contain this isolated current-SDK
reproduction.

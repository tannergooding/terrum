# CA5390 spends 42 seconds analyzing byte-array writes without encryption APIs

> [!NOTE]
> Drafted with AI assistance from measured SDK analyzer timings.

### Environment and reproduction

Windows x64 (10.0.26200), .NET SDK `11.0.100-rc.1.26425.128`, MSBuild
`18.11.0-1.26425.128+3551975be`; bundled
`Microsoft.CodeAnalysis.NetAnalyzers.dll` file version `11.1.26.42628`.
In a `net11.0` class library, set `AnalysisLevel=latest-all` and
`ReportAnalyzer=true` (CA5390 is otherwise disabled by default). Use literal
repeated source call sites, not a runtime loop:

```csharp
using System;
using System.Collections.Generic;

public sealed class Encoder
{
    private readonly List<byte> _bytes = new();
    private void Bytes(params byte[] values) => _bytes.AddRange(values);

    public int Emit()
    {
        Bytes(0x48, 0x89, 0xC8, 0x48, 0x89, 0xC8, 0x90, 0x90);
        // Repeat this call at 2,047 more distinct source locations.
        return _bytes.Count;
    }
}
```

There is no encryption API or key-consuming sink. A forced Release rebuild
(`dotnet build -c Release -t:Rebuild -p:ReportAnalyzer=true -v:diag`) took
**53.97 seconds process wall time** for 2,048 `params byte[]` sites. The
analyzer report attributed **42.179 seconds to CA5390** and **10.426 seconds
to CA5403**. Changing only the helper parameter to
`Bytes(params ReadOnlySpan<byte> values)` reduced each rule's reported time to
**<0.001 seconds**; wall time was **1.71 seconds**. Analyzer-seconds are not
wall time and can overlap.

### Project-scale impact

A C# compiler host's Release rebuild took **23:00.29 wall time**; its core
project reported **693.321 CA5390 analyzer-seconds**, **1,324.598 CA5403
analyzer-seconds**, and 2,220.343 analyzer-seconds for all analyzers. In a
later snapshot, after changing byte-array helpers and other source, the build
took **2:10.41 wall time**, with **0.443 CA5390** and **0.485 CA5403
analyzer-seconds**. Analyzer execution can overlap each other and wall time;
these project snapshots do not isolate the effect of one code change.

### Investigation request

[CA5390](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/quality-rules/ca5390)
finds hard-coded data used as encryption keys. Please investigate why the
repeated byte-array call sites are costly when no key-consuming sink exists,
and add this input as a performance regression test. The expensive internal
step remains unknown.
The [CA5390 implementation](https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Microsoft.CodeAnalysis.NetAnalyzers/Microsoft.NetCore.Analyzers/Security/DoNotHardCodeEncryptionKey.cs)
and
[CA5403 implementation](https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Microsoft.CodeAnalysis.NetAnalyzers/Microsoft.NetCore.Analyzers/Security/DoNotHardCodeCertificate.cs)
both derive from `SourceTriggeredTaintedDataAnalyzerBase`. The existing
[joint tracking issue](https://github.com/dotnet/roslyn-analyzers/issues/6737)
covers their known performance problems.

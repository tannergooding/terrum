# CA5390 spends over 11 minutes on byte-array opcode emission with no encryption keys

> [!NOTE]
> Agent-drafted issue report; measurements and reproducer should be checked before posting.

**Upstream:** `dotnet/sdk` owns the bundled .NET analyzers
([migration notice](https://github.com/dotnet/roslyn-analyzers)).
The [existing issue covering both CA5390 and CA5403](https://github.com/dotnet/roslyn-analyzers/issues/6737)
already flags known performance problems and possible removal; these data may
belong there rather than in a duplicate issue.

**Environment:** Windows x64; SDK/MSBuild `11.0.100-rc.1.26425.128` /
`18.11.0-1.26425.128+3551975be`; bundled
`Microsoft.CodeAnalysis.NetAnalyzers.dll` file version `11.1.26.42628`
(product version `11.0.100-rc.1.26425.128+3551975be08744f0418857c5bed8ab1545c5dd47`).
The original host targeted `net11.0` with `AnalysisLevel=latest-all`
and warnings as errors. CA5390 is otherwise disabled by default.

**Standalone reproduction:** Run the accompanying `generate.ps1` with
`-Calls 2048 -OutputDirectory .\repro`, followed by
`dotnet build .\repro\AnalyzerRepro.csproj -c Release -t:Rebuild -v:diag`.
It generates a project with independent build props and 2,048 separate
calls to a byte-array opcode helper:

```csharp
private void Bytes(params byte[] values) => _bytes.AddRange(values);
// In Emit():
Bytes(0x48, 0x89, 0xC8, 0x48, 0x89, 0xC8, 0x90, 0x90);
```

The source never supplies an encryption key to a crypto API. Repeat with
`-Calls 0`, `128`, `512`, and `2048`, then with `-Span` to change only
the helper signature to `params ReadOnlySpan<byte>`. Diagnostic verbosity
prints CA5390 analyzer time; measure process wall time separately.

| Sites | Signature | Process wall time | CA5390 analyzer time | CA5403 analyzer time |
|---:|---|---:|---:|---:|
| 0 | `byte[]` | 1.51 s | <0.001 s | <0.001 s |
| 128 | `byte[]` | 0.89 s | 0.004 s | 0.059 s |
| 512 | `byte[]` | 1.35 s | 0.024 s | 0.707 s |
| 2,048 | `byte[]` | 53.97 s | 42.179 s | 10.426 s |
| 512 | `ReadOnlySpan<byte>` | 1.69 s | <0.001 s | <0.001 s |
| 2,048 | `ReadOnlySpan<byte>` | 1.71 s | <0.001 s | <0.001 s |

The first run includes project setup, so process times are not isolated
analyzer benchmarks. The 2,048-site case reproduces a sharp increase in
CA5390 cost with no cryptographic APIs; replacing only the parameter type
removes it. It is not a 693-second standalone reproduction.

**Larger real-world scenario:** A C# compiler host with many byte-emission
sites originally took
`23:00.29` wall time and core-project CA5390 analyzer execution was
`693.321 s` (CA5403 `1324.598 s`; all analyzers `2220.343 s`).
After a span-based emitter change, with **both rules still running**, the Release
rebuild was `2:10.41` wall time, CA5390 took `0.443 s`, CA5403 `0.485 s`,
and all core analyzers `187.173 s`. Analyzer execution times can overlap
each other and wall time. The two full-project snapshots span other feature
changes; they show a strong association, not a single-change controlled
causal proof.

**Workaround:** Change `Bytes(params byte[] values)` to
`Bytes(params ReadOnlySpan<byte> values)` and move a few byte
encoding/write calls behind helpers. PE SHA-256 output hashes
for both measured native samples matched before and after. All analysis
remained enabled. For an exact attribution, compare individual byte-array
call-site changes at the same commit while holding the rest of the input fixed.

**Expected:** A source file with no key supplied to `AesGcm`, `AesCcm`, or
`SymmetricAlgorithm` should not take minutes for this rule just because many
small byte arrays exist. See the
[CA5390 rule definition](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca5390)
and [SDK implementation](https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Microsoft.CodeAnalysis.NetAnalyzers/Microsoft.NetCore.Analyzers/Security/DoNotHardCodeEncryptionKey.cs).

**Suspected shared cause, not established:** Both rules use
`SourceTriggeredTaintedDataAnalyzerBase`; CA5390 additionally treats some
constant byte arrays of key-like lengths as taint sources
([source specification](https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Utilities/FlowAnalysis/FlowAnalysis/Analysis/TaintedDataAnalysis/HardcodedSymmetricAlgorithmKeysSources.cs)).
The parallel collapse of CA5390 and CA5403 when ordinary byte-emission code
changed suggests redundant or expensive shared flow analysis. No trace yet
establishes whether the expense is source enumeration, flow computation,
caching, or another shared stage.

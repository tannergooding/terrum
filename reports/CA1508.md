# CA1508 dominates analyzer time in a small C# library

> [!NOTE]
> Drafted with AI assistance from measured SDK analyzer timings.

### Environment

Windows x64 (10.0.26200), .NET SDK `11.0.100-rc.1.26425.128`, MSBuild
`18.11.0-1.26425.128+3551975be`, bundled
`Microsoft.CodeAnalysis.CSharp.NetAnalyzers.dll` file version `11.1.26.42628`.
The `net11.0` library has 46 source files (~836 KB), `AnalysisLevel=latest-all`,
`EnforceCodeStyleInBuild=true`, and trimming/AOT analysis enabled.
CA1508 is otherwise disabled by default.

### Standalone pattern (does not reproduce the project hotspot)

In a `net11.0` class library, enable `AnalysisLevel=latest-all`,
`Nullable=enable`, and `ReportAnalyzer=true`. This method uses 80 mutable aliases
and 256 distinct conditional branches; declare and assign the omitted locals in
the same chain pattern:

```csharp
public static int Evaluate(int input)
{
    var score = 0;
    object? v0 = input;
    object? v1 = input;
    // Declare v2 through v79 the same way (80 distinct mutable aliases).

    if (input == 0)
    {
        v0 = new object();
        v1 = v0;
        // Assign v2 = v1; ...; v79 = v78.
    }
    else
    {
        v0 = v79;
        v1 = v0;
        // Assign v2 = v1; ...; v79 = v78.
    }
    if (v79 == v0) { score++; }

    // Repeat the branch/assignment/comparison block 255 more times,
    // with distinct conditions input == 1 through input == 255.
    return score;
}
```

Build with `dotnet build -c Release -t:Rebuild -p:ReportAnalyzer=true -v:diag`
and inspect `CSharpAvoidDeadConditionalCode (CA1508)`. For the control, add
`-p:RunAnalyzers=false`. This case measured
**0.755 CA1508 analyzer-seconds** and **2.98 seconds process wall time**; with
all analyzers disabled, wall time was **1.26 seconds**. It exercises conditional
flow analysis, but does **not** reproduce the project's 163-second CA1508
measurement.

### Project-scale measurements

In a diagnostic Release rebuild, CA1508 accounted for **162.765
analyzer-seconds** of **187.173 aggregate core-project analyzer-seconds**;
trimming analysis reported 18.991 seconds. That build took **2:10.41 wall
time**. A separate earlier full rebuild took **23:00.29 wall time**; its
analyzer table attributed 1,324.598 seconds to CA5403 and 693.321 to CA5390.
The 2:10.41 snapshot also reported 0.485 CA5403 and 0.443 CA5390
analyzer-seconds. The earlier snapshot contained other source differences;
analyzer-seconds can overlap one another and wall time, so they are not
additive or directly comparable to elapsed time.

Later forced Release rebuilds of the three-project solution took **178.96**
and **198.78 seconds wall time** (178.503 and 198.195 seconds in `Csc` tasks).
In warmed no-restore rebuilds, disabling CA1508, CA5403, and CA5390 took
**2.67 / 2.95 / 2.83 seconds wall time**; disabling all analyzers took
**1.29 / 1.22 / 1.26 seconds**. The difference implicates this group, but
does not isolate CA1508's wall-time contribution.

### Investigation request

[CA1508](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/quality-rules/ca1508)
performs non-constant-value dataflow analysis, and its documentation notes
that analysis can increase compile time. The
[analyzer implementation](https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Microsoft.CodeAnalysis.NetAnalyzers/Microsoft.CodeQuality.Analyzers/Maintainability/AvoidDeadConditionalCode.cs)
registers operation-block actions and calls
`ValueContentAnalysis.TryGetOrComputeResult` for eligible bodies. Please
identify the operation block(s) responsible for the project-scale cost and
add a focused performance regression test. The standalone pattern does not
identify that hotspot. The goal is to retain CA1508's useful diagnostics
without this build-time cost.

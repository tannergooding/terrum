# CA5390 and CA5403 slow byte-array emission without cryptographic sinks

> [!NOTE]
> Drafted with AI assistance from measured SDK analyzer timings.

### Environment and reproduction

Windows x64 (10.0.26200), .NET SDK `11.0.100-rc.1.26425.128`, MSBuild
`18.11.0-1.26425.128+3551975be`; bundled
`Microsoft.CodeAnalysis.NetAnalyzers.dll` file version `11.1.26.42628`.
In a `net11.0` class library, set `AnalysisLevel=latest-all` and
`ReportAnalyzer=true` (both rules are otherwise disabled by default).
Use 2,048 literal call sites, not a runtime loop:

```csharp
using System;
using System.Collections.Generic;

public sealed class Encoder
{
    private readonly List<byte> _bytes = new();
    private void Bytes(params byte[] values) => _bytes.AddRange(values);

    public int Emit()
    {
        Bytes(0x48, 0x89, 0xC8, 0x48, 0x89, 0xC8, 0x90, 0x90);
        // Repeat this call at 2,047 more distinct source locations.
        return _bytes.Count;
    }
}
```

There are no certificate or encryption APIs. Build with
`dotnet build -c Release -t:Rebuild -p:ReportAnalyzer=true -v:diag`;
diagnostic verbosity prints per-rule timings. Then change only the helper
signature to `Bytes(params ReadOnlySpan<byte> values)` and rebuild:

| Signature | Build process wall | CA5390 analyzer | CA5403 analyzer |
|---|---:|---:|---:|
| `params byte[]` | 53.97 s | 42.179 s | 10.426 s |
| `params ReadOnlySpan<byte>` | 1.71 s | <0.001 s | <0.001 s |

Analyzer times can overlap each other and wall time; they are not additive.
Both rules are enabled in both builds. The only standalone source change is
the helper's parameter type, which preserves the eight bytes written.

### Project-scale impact

A C# compiler host's Release rebuild took **23:00.29 wall time**; its core
project reported **693.321 CA5390 analyzer-seconds** and **1,324.598 CA5403
analyzer-seconds**. In a later snapshot, after changing byte-array helpers
and other source, the build took **2:10.41 wall time**, with **0.443 CA5390**
and **0.485 CA5403 analyzer-seconds**. Those snapshots are not an isolated
A/B test; two representative emitted PE images retained identical SHA-256
hashes. The standalone reproduction above isolates the helper signature.

### Investigation request

[CA5390](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/quality-rules/ca5390)
checks hard-coded encryption keys; its
[constant-array source definition](https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Utilities/FlowAnalysis/FlowAnalysis/Analysis/TaintedDataAnalysis/HardcodedSymmetricAlgorithmKeysSources.cs)
includes eight-byte arrays.
[CA5403](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/quality-rules/ca5403)
checks hard-coded certificates. Their
[CA5390](https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Microsoft.CodeAnalysis.NetAnalyzers/Microsoft.NetCore.Analyzers/Security/DoNotHardCodeEncryptionKey.cs)
and
[CA5403](https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Microsoft.CodeAnalysis.NetAnalyzers/Microsoft.NetCore.Analyzers/Security/DoNotHardCodeCertificate.cs)
implementations both derive from `SourceTriggeredTaintedDataAnalyzerBase`.
Please investigate why both spend time on these calls with no cryptographic
sink and add this input as a performance regression test. The shared trigger
does not establish a shared internal root cause. The existing
[joint tracking issue](https://github.com/dotnet/roslyn-analyzers/issues/6737)
notes their known performance problems.

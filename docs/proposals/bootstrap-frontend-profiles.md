## Invocation and persistence obligations

The profile fingerprint binds scanner requirements, writable Frontend and
FrontendProgram descriptors/capacities, v88 layout and comparison summary,
resource ceilings, runtime policy and entry/result convention. Persist
symbolic requirements and operations, not seed values, addresses or trusted
analysis. Read/link/replacement must compare exact requirements.

The candidate scalar int32 entry result reports the scanner token count only
after successful complete publication/decoding; nonpositive results are
failure, not a valid empty program. The host rejects incompatible identity,
access, type, capacity, source, publication or summary and returns only owned
audited snapshots after completion. Invocation storage is fresh and writable
outputs are disjoint. Preserve source/policy/publication/program before the
summary overwrites scratch; audit the originals and compare all 2,274 words,
including unused slots.

The separate
[private-span recommendation](token-span-semantic-module.md) has a concrete
frontend corpus and provisional revision-77 implementation. It needs
snapshot-to-span, parameters/calls, length, unsigned indexing, copies and
retirement, not TokenCursor storage/AdvanceOne, returned views or public span
signatures. Compatible replacement must preserve type roles and rederive
backing/lifetime obligations after local remapping; revision-76 span rejection
remains intact.

Validate both runtime policies, retained snapshots and differently sized
seeds, source/token/function/frame boundaries, exact and corrupt identities,
source/signature-compatible retargeting, summary/program corruption and
replacement. Keep ordinary frontend AOT/JIT, scanner-only parity and source
audit distinct. No hosted parsing substitute, precomputed/captured publication,
scanner-only success or source-free bootstrap-compiler claim is permitted.

Source-grant adapters are temporary bootstrap/test infrastructure documented
in the [implementation inventory](../../self-host/README.md#source-and-managed-component-contracts),
not a public ABI promotion worklist. Prefer ordinary explicit inputs and proper
unit tests as compiler support develops; no external source grant is selected.

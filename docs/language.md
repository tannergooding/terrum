# Terrum language design

Terrum (TAIR-um), from TerraFX, is a proposed C#-shaped language for applications through systems code. Proposed tools are `terrum` and `terrumc`. This document describes the intended language, **not a claim of complete implementation**: the compiler supports lossless syntax and a bounded [native integer/bool profile](native.md). The status of examples is documented in [samples](samples.md); implementation staging is in [implementation](implementation.md), and the proposed API inventory is in [libraries](libraries.md). Source spellings throughout the design samples are provisional.

## Accepted direction

- C#/.NET application and API ergonomics are the baseline; ownership, access, representation, lifetime, effects and placement are distinct contracts. An application can use managed cyclic graphs without propagating lifetime parameters through every edge; unique native resources and deterministic cleanup remain nonduplicable. There is no implicit copy, boxing, pinning, retain, synchronization or materialization to repair an invalid program.
- AOT and JIT must implement the same semantics for supported features. Independently serviced modules, DLLs and plugins require published, versioned contracts and binding-time compatibility; closed-world optimization or implementation pinning is explicit. The initial backend emits Windows x64 native code; the C#/.NET compiler host does not define Terrum's type system, semantic IL or permanent ABI.
- Concrete types are sealed by default; interface inheritance and composition replace general concrete inheritance. Public namespaces express concepts, not library tiers. Public source visibility is `public`, `internal` (module) and `private` (declaring type); there is no protected-family or friend-module access through `unsafe` or linking. Author-approved generation may act within the declaring module's implementation scope, but grants no consumer private access. A public Terrum surface is not automatically a native export.
- Exceptions propagate exceptional failures; expected alternatives use conditional outputs or domain statuses. Recovering with `catch` requires an unsafe recovery context; cleanup and `try/finally` do not. Unsafe recovery does not prove an object's invariant has survived. Platform callbacks must contain faults or terminate rather than unwind across a foreign ABI.
- Type, declaration, interface and metadata contracts are authoritative. A compiler may infer private implementation facts but cannot silently publish stronger or weaker promises from a replaceable body. Consumers bind against the producer's resolved contracts and rule version, not their own reinterpretation of its source defaults. [Lifetimes](lifetimes.md) specifies this distinction for borrowed results.

### Types and operations

`var` binds a nonwritable inferred value; `mut var` permits rebinding. `ref T` is a read place loan, `mut ref T` an exclusive writable place loan, and `out T` initializes a vacant destination. Fields are read-only after construction unless `mut`; a fixed binding may still hold a writable view or mutable class handle. Constructor initialization does not imply later mutation permission. Loans are place- and flow-sensitive, ending after last use; overlapping read loans are allowed, conflicting write loans are not. A writable binding cannot upgrade a readonly referent.

An ordinary `struct` is inline and promises checked `[Copy]`; every field must support a code-free, allocation-free copy without duplicating a unique obligation. Adding a destructor or unique field must fail the declaration instead of silently removing that public capability. A `unique struct` or `unique union` is noncopyable even if its bytes look trivial. An ordinary `class` uses aliasable managed handles; copying a handle shares its object, not its payload. A `unique class` has a unique owning handle, not necessarily a unique reachable graph or a prohibition on GC. `unique` restricts duplication; `move` explicitly transfers a named value (including a copyable value when invalidating its source is desired). By-value copy/consume is based on the **complete qualified form**, not merely the payload declaration. A moved handle need not relocate the payload; large `[Copy]` values are not assumed cheap.

Representation projections are separate: `val<T>` denotes eligible inline payload; `box<T>` reference form; `ref<T>` bounded loan; `own T` currently denotes a GC-free unique native allocation owner. Compatible `box<C>` is `C`, nested `box` normalizes, and `box<T?>` is `box<T>?`; normalization does not allocate or invent a clone. Explicit `AsBox` can reuse an existing reference or allocate for an eligible inline value while preserving qualifiers and absence. `val<box<S>>` names a payload type without extracting it. `val<C>` remains conditional on explicit inline-payload, identity, copying and address-stability rules; class-handle aliasing cannot be silently inherited by inline storage. Scoped loans, arbitrary cleanup obligations and raw pointers cannot be boxed to escape restrictions. The exact ownership-policy transition and first-class stored-loan syntax remain open.

There is no universal `default(T)`: live fields and active union payloads must be initialized. Explicitly repeated optional modifiers (`int32??`, `T??`, including intervening trivia) are syntax errors. Optional construction remains semantically idempotent: substituting `T = int32?` into `T?` yields `int32?`, not a second presence layer. `Option<T>` likewise normalizes an optional payload rather than adding a presence layer. Modifiers on distinct nested types, such as `List<int32?>?`, are valid. `is some` yields the canonical payload, and `is null` tests absence. Nominal unions preserve distinct cases such as `Missing` versus `Found(null)`; `with` updates need separate `Unchanged`/`Set(null)` states. `T?` and `box<T>` are non-injective projections, so inverse generic inference cannot guess a unique original type. Normalization precedes signature identity/overload checks, without flattening nominal wrappers. Niche encodings must be declared validity/ABI contracts (e.g. reserved `-1` for nonnegative `int32`, zero for nonzero `int32`, null for a non-null reference); invalid encodings and padding are not free option states. Imports and mutations preserve validity.

Integer-backed `enum` values include unnamed underlying values; `[Flags]` explicitly defines bit-set operations. Closed nominal tagged `union` cases have active-payload validity; an explicitly overlapping native layout does **not** establish it. `[Layout(Sequential)]`, `[Layout(Union)]` and explicit offsets need separate validated calling-ABI profiles. Structural `T | U` unions, especially overlapping alternatives, are undecided.

### Interfaces, access and generic properties

`where T : IFoo` requires a checked behavioral witness; `where T : [Sized]`, `[Copy]`, `[ManagedStorable]`, `[Send]`, `[Sync]`, `[TextCodeUnit]` or `[NativeComInterface]` asks for a compiler-verified property of the complete form, **not** implementation of an `I...` interface or the mere presence of an attribute. `[Sized]` does not promise a size constant in shared generic code. `[TextCodeUnit]` admits `char8`, `char16`, `char32`, not arbitrary valid encoded text. Native COM additionally requires checked IID, inherited slots, signatures, layout and lifetime. User shape generation can provide witnesses or adapters only after checking costs, ownership and ABI.

Multiple behavioral interface bases retain declaring-member identity through diamonds. Conflicting requirements require disambiguation or an adapter; initial support has no stateful bases or default-method linearization. A generic `IRandom` call through `mut ref TRandom` mutates the borrowed inline value without defensive copying or boxing; storing `TRandom` additionally requires `[Sized]`. An explicit `dyn IRandom` has its own chosen borrowing/ownership, root, lifetime and dispatch contract. Generic pointer and stored-loan arguments are intended where their actual storage, tracing and lifetime properties permit them, not prohibited categorically because the initial managed `List<T>` is narrower. Sizeless scalable vectors can satisfy behavior without satisfying `[Sized]`.

One access-qualified `Span<T>` and one qualified collection-interface family avoid nominal readonly/writable duplicates. Matching access never upgrades a readonly source through a returned view; fresh construction can produce independent writable storage, but shallow copying cannot upgrade retained aliases. Structural read access protects the container, not independently mutable element handles; graph-read attenuates all references obtained through a root; immutable graphs exclude writes through *all* aliases for the defined extent. Readonly is neither immutability nor purity. Checked `[Pure]` additionally excludes observable writes, I/O, identity-producing allocation, ambient mutable state, volatile/atomic observation and synchronization. Repeated-call reuse needs stable observations, equivalent inputs and compatible code identity; mutable inputs can change between pure calls. Dynamic effects/read regions belong to interface and module contracts.

The working `IContiguousSequence<T>.AsSpan()` returns a read projection. `Span<T>` implements it **explicitly**, permitting constrained generic calls without a redundant concrete `span.AsSpan()` member. Known-code-unit `TextSpan<TCodeUnit>.AsSpan()` and `Text.AsSpan()` stay public because those change the view; erased `TextSpan<void>` has no `AsSpan()` or `IContiguousSequence<void>`. A stored or returned view must preserve its opaque backing dependency, even for empty/end slices. Detailed receiver and backing rules are in [lifetimes](lifetimes.md). `ISequence<T>` traversal and associated borrowing contracts remain to be specified. Working `Task<TResult = void>` makes `Task` precisely `Task<void>` after type-argument expansion, not an independent task protocol; type-default syntax remains open.

Declared [type families](type-families.md) can expose checked common operations and conditional members/conformance. A static parameter meaning "any fixed vector of float32" preserves its actual type, width and associated mask, including same-instantiation relationships between operands/results; it does not require users to introduce a nominal `ISimdVector` solely to name the family. Runtime interchange that hides an encoding is different from preserving an unspecified static instantiation. Erased forms are explicit family contracts, never an automatic `Type<T>` to `Type<void>` rule; copy/move, tracing, cleanup, lifetime and ABI obligations survive. `Task<void>` still means no result, not permission to discard an arbitrary owning result.

### Primitives, strict arithmetic and text

Width-explicit integers `int8` through `int128` and unsigned counterparts, distinct target-size `nint`/`nuint`, IEEE binary `float16/32/64/128`, `bfloat16`, IEEE decimal `decimal32/64/128`, raw `char8/16/32`, validated scalar `rune`, `bool` and `void` are the proposed families. `simd64/128/256/512<T>` are fixed ABI shapes; `simd<T>` is genuinely hardware-scalable and initially sizeless, not an unspecified preferred width. BID versus DPD decimal representation, native-integer names and precise vector-family syntax remain open; the decimal value semantics do not become CLR `System.Decimal`.

Numeric literals have **no fallback type**: an expected type, typed operand or explicit tag must disambiguate; `var x = 1` and unconstrained `F(1)` diagnose. Contextual literal construction rounds/validates directly in the selected format; it is not conversion from a hidden `int32`/`float64`. Known arguments/targets may establish generic context first, but ambiguous cases diagnose and tags commit a type. Already-typed numbers require explicit conversions. Ordinary numeric casts select a published checked conversion; checked does not mean exact. Integer arithmetic and extent arithmetic are checked in every build. Division truncates toward zero; signed minimum divided by `-1` fails while its remainder is zero. Shift counts are checked; left shift is width-truncating bit manipulation, not checked multiplication. Wrapping and saturating operations are explicit. Floating operations use target-format round-to-nearest ties-even without implicit FMA, reassociation, ambient rounding or flush dependence; arithmetic NaNs canonicalize in the working profile, while bitcasts/copies preserve bits. [Conversion policies](conversions.md) distinguish range, fractional rounding, modulo narrowing, nonfinite handling and bit reinterpretation. Numeric-key comparer semantics (all NaNs equal, signed zeros equal, decimal cohorts normalized) are separate from IEEE operator equality.

Source text is UTF-8; runtime text has **no default encoding**. The single `TextSpan<TCodeUnit = void>` family has immutable validated `char8`/`char16`/`char32` members and a family-declared encoding-erased `void` specialization: bare `TextSpan` is exactly `TextSpan<void>`. Here `void` does not mean zero-size units or a default encoding. Erasure needs no text copy/transcoding and retains actual encoding, backing, access and lifetime/lease dependencies. Checked typed projection rejects a mismatched representation rather than transcoding; only known-code-unit forms expose typed `AsSpan` and contiguous-sequence conformance. Common `IsEmpty`, ordinal and formatting operations work on either form. A raw `AsSpan()` can forget text validity but not immutable backing, access, lifetime or rooting. Raw slices can split scalars; text slices must preserve scalar boundaries. Editing copies into mutable raw storage or a builder, then validates and freezes before publication; transferring an exclusively held initial buffer may avoid a copy only by revoking all writes. Readonly aliasing or validation alone cannot establish immutable text. Final storage, string facade, adaptive/block/RLE representation and projection ABI require experiments.

Design-only character literals carry one scalar, target-typed to a representable code-unit/scalar type without a numeric or UTF-16 fallback. Registered text targets provide `rune` context and forward scalar fragments directly through the writer protocol. A raw `char8` is not automatically a valid standalone UTF-8 scalar. Precise representability rules and the current unsupported-syntax boundary are in [conversions](conversions.md#character-intent).

Defaults are **ordinal plus invariant together**: exact Unicode scalar sequence equality and scalar ordering across encodings, matching hash, no implicit normalization/casing/linguistic comparison, and ASCII digits/signs/punctuation for numeric parsing and formatting. U+0661/U+FF11 digits and U+2212 minus do not act like ASCII tokens. Arbitrary valid Unicode remains valid text data. Termination, embedded-zero exclusion, pinning and lifetime are distinct native-string requirements. `Text` is a common payload/facade with ordinary ownership forms; `own Text` is an explicitly supported native storage form whose immutable contents do not make its owning handle copyable.

### Construction, errors and effects

Ordinary explicit constructors are baseline. Independent opt-in `Generate` operations can supply construction, equality/hash, deconstruction, formatting and combined validated withers from declared storage/mappings; no field-name magic, automatic primary-constructor capture, implicit successive setters or parameter-name-only overload distinctions. Omitted update members are `Unchanged`, not a null/default value. Affine and class withers need explicit failure, cleanup, allocation and identity behavior.

Constructor type arguments can be inferred from known argument/target types before contextual literals are constructed. `new DifferentRandom(new CounterRandom(0), 0xA5A5A5A5)` infers `TRandom` from the first argument and uses the declared `uint32` seed/mask types for its literals. It does not infer field capture, change ownership, choose types from constraints or invert optional/box normalization.

Parsing uses `IParsable<TSelf>.TryParse(TextSpan, out TSelf)` including user types. Bool-plus-`out` declarations publish all outputs on true and leave them vacant on false without annotations on every API; other returns initialize them on every normal return unless an explicit condition such as `[OutputWhen]` says otherwise. Failure cleans partially initialized values, never fabricates `default(T)`; async `out` publication occurs at operation completion. Expected invalid input normally branches on `Try...`/status. Domain outcomes may use response types; there is no mandatory language-wide `Result` or implicit catch-and-continue.

`require predicate;` is a normal user-facing checked boolean requirement: evaluate the predicate once, continue on true, and throw a requirement-failure exception on false **in every build**. It accepts general predicates (`require format.IsEmpty;`) and lifts bool/out success (`require int32.TryParse(text, out var x);` makes `x` available afterward). Status APIs require an explicit success predicate, such as `require status == CalculateStatus.Success;`, using the declaration's output relationship. It is not a debug assertion, optimizer assumption, catch or silent status conversion; exceptional/partial-output cleanup remains intact. Metadata exposes resolved success/output/effect contracts to ordinary tools and consumers. The call-site requirement itself belongs to semantic code/IR, not a body-inferred public precondition or framework-private intrinsic. Syntax and simple boolean requirements are implemented; the explicit native fail-fast profile terminates on false instead of providing this future exception/cleanup runtime. Conditional outputs and the ordinary exception identity/ABI remain unimplemented.

Formatting uses one `IFormattable` → `ITextWriter` protocol with typed fragments/values, no obligatory allocating formatter per type. Target-typed interpolation and collection expressions register explicit construction shapes, not arbitrary similarly named methods. Holes evaluate once left-to-right into typed captures before segments drain; `{ref value}` is a provisional borrowing spelling, and named unique transfers require `move`. Nested formatting forwards the same writer so a Point and its scalar fields can reach a custom handler without temporary strings or boxing. Refusal stops future writes but cannot undo prior output or hole evaluation; no replay, rollback or transactional stream guarantee. Owning text publishes only after full validation/freeze and cleans partial storage. Collection spreads enumerate once in order; builders own accepted elements, clean rejected consumed elements and abandon partial state exactly once. Builder arguments, handler registration and resumable async formatting are open. Synchronous formatter refusal is not a resumable continuation.

Allocation, GC, rooted reads/writes, blocking, suspension, I/O, atomics, throwing/no-throw, normal/no-return, cleanup and retirement are independently expressible effect bounds, finer-grained than Core/Foundation/Application dependency layers. `void` is the single zero-data result type, with value `()`, usable as `Func<void>` and `Task<void>`; `Option<void>` still represents two states. A checked `[DoesNotReturn]` on a `void` call removes its normal continuation but retains exception/cleanup edges; `[NoThrow]` is separate. A verified implementation cannot normally return, including by completing a task that terminates *later*. There is no public `unit` or `never` primitive; the compiler may use internal bottom flow. Removing an exported no-return guarantee breaks callers that rely on it.

### Storage, concurrency, entry and boundaries

Tracing GC handles aliased/cyclic application graphs; ownership handles deterministic native storage and resources. A unique owner may still refer to GC storage; a GC root does not keep a logically disposed native allocation valid. Distinguish storage acquisition, initialization, close, value destruction, storage release and eventual reclamation. Vacant/partially initialized/live/retired states, reverse-order partial cleanup, no-throw/non-suspending scope cleanup, direct destination construction and stable-address requirements must be checked. Replacing a live value builds the replacement before dropping the old one; explicit reconstruct-in-place may leave vacancy on failure. Pool leases revoke access on return; deferred dead-storage retirement differs from deferred live-value cleanup, with one retirement owner after commitment and explicit completion endpoints.

Ordinary mutable access is local/nonconcurrent, not intrinsically bound to an OS thread. `[Send]` transfers actual authority; `[Sync]` governs sharing; neither follows from GC, `[Copy]` or readonly. A checked `ListWriteAccess` guard arbitrates *all* aliases/reentrancy before mutable span access, without silently registering failed static loans or becoming a cross-thread mutex. A managed `LinkedList<T>` retains node identity through remove/reinsert; `Clear` detaches even externally held nodes. Wrong-list/preflight failures leave the structure unchanged; enumeration fails after structural mutations, not mere payload replacement. Common collection semantics and examples are in [samples](samples.md) and [libraries](libraries.md).

Tasks are scope-owned and structured; cold start is a **recommendation**, not a frozen contract. Cancellation does not establish completion of external buffer use, and suspension cannot extend invalid loans. Entry conventions are `Main` returning `void`/`int32` or `MainAsync` returning `Task`/`Task<int32>`, with no arguments or `Span<TextSpan> args` excluding the program name. Host-selected arguments/rooting last through async completion and structured cleanup; `async` describes implementation, `Async` describes API behavior, and no implicit blocking bridge is inserted. `Terminal.Write`/`WriteLine` default to standard output; `output: TerminalOutput.Error` selects stderr, with writer access for composition. Redirected streams work without an interactive terminal; terminal controls require endpoint capabilities.

Recommended continuation policy: no ambient `SynchronizationContext`-style capture by default and no pervasive per-await `ConfigureAwait(false)`. Explicit execution/affinity scopes or declarations govern thread-bound/UI continuations, including cleanup and cancellation. Generic library code composes through those declared requirements without acquiring accidental UI dependencies. No capture is **not** "always switch to a thread pool": synchronous continuation is allowed, logical serialized authority need not mean one OS thread, and non-Send/affine state must never migrate unsafely. A caller's explicit UI obligation remains valid across a library call without imposing it on every internal continuation. Scheduler/awaiter syntax, propagation and boundary validation still need design; there is no implemented async runtime.

Reflection respects visibility, access, lifetime and trimming. Symbol-resolved tokens and compiler-checked `[ConstantExpected]` names (including through wrappers) support safe bounded lookup; open-ended runtime discovery or private access needs a *different* privileged unsafe API, explicit authorization and retained targets. Retention of layout, executable bodies, descriptors and debugging data is independent. Author-authorized deterministic generation can inspect its own defining module's private members but cannot grant consumers friendship or bypass normal checks. Foreign declarations specify native symbols, calling conventions, layout, ownership, callback teardown, exception containment and marshaling costs; COM requires exact profiles, not behavioral-interface resemblance.

The proposed portable structured semantic IL carries typed blocks/arguments/edges, values and memory places, loop/exception/cleanup regions, roots, checked operations, construction and suspension, with validation of dominance, ownership and region consistency. It is **not** CLI IL. The initial backend lowers a smaller verified structured representation directly to Windows x64 machine code, without CIL or LLVM. LMOD remains a provisional versioned module container for semantic types/signatures, layout/ABI, bodies, dependencies, roots, foreign profiles and native caches. Contract-bound vs implementation-pinned replacement is independent of static vs dynamic linkage. Unchanged JIT/AOT consumers must reject incompatible capture, output, access, layout and effect changes; AOT-only deployment cannot secretly require a JIT. The first single-image PE emitter does not implement these separate-module contracts. Generic specialization, sharing and explicit scenarios need enforceable ABI/dictionary/rooting rules; unsupported strict codegen policies must fail instead of silently boxing or duplicating code.

## Provisional source notation and open decisions

The design examples use `own`, `move`, bracketed checked predicates, `[ViewOf]`, `[Captures]`, `[OutputWhen]`, `[Pure]`, `[MatchedAccess]`, `require`, `{ref value}`, `[TextTarget]`, `[TextBuilder]`, `[CollectionBuilder]`, `[NativeExport]`, `utf8z`/`utf16z` literals and generic trailing defaults as **illustrations**, not frozen syntax or implemented compiler promises. Exact member-contract relationship syntax, conditional copy capabilities, first-class stored-loan qualifiers, span-anchor layout and calling ABI, inline `val<C>`, native ownership transition, structural unions, decimal encoding, text storage, wither omission/overloads, handling/registration, async start/cancellation, generic dispatch selectors and exception ABI remain open. The applicable accepted semantics and current implementation limits are distinct; syntax should follow checked contracts rather than determine them.

## Current implementation limit

The current compiler binds and verifies a bounded `int32`/`bool`/`void` profile and emits native Windows x64 executables. Its explicit fail-fast runtime is not the language's future catchable-exception runtime. Ownership/lifetime analysis, managed graphs, general semantic IL/LMOD and source-compatible standard libraries remain future stages. Syntax-only commands do not validate semantic obligations; native builds diagnose unsupported constructs rather than silently weakening them. See [implementation](implementation.md) and [native](native.md) for actual support, [roadmap](roadmap.md) for staging and [samples](samples.md) for the distinction between runnable examples and broader design sketches.

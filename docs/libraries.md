# Standard-library design

This is the proposed Terrum library contract, not the installed .NET library or an implemented Terrum runtime. The `.api.terrum` inventories in [`library`](../library) and the [numerics/tensors example](../samples/design/numerics-and-tensors.terrum) are **DESIGN ONLY**. The current P0 host is a syntax-only front end: it does not bind these declarations, lower semantic IR or execute the examples ([implementation staging](implementation.md)). [Language](language.md) defines the broader value/effect rules; [lifetimes](lifetimes.md) defines the access and dependency model.

## Dependency layers and package boundaries

| Cumulative layer | Representative surface | Required substrate |
|---|---|---|
| **Core** | Numeric primitives and protocols, `void`/options, `Span<T>`, immutable code-unit/text views, static eager algorithms, shape/view and SIMD contracts | Checked value execution, bounds/access and cleanup/failure services; no ordinary-path allocation or OS facility |
| **Foundation** | Explicitly owned buffers/vectors/maps, allocators/arenas/pools, owning native `Text`, persistent tensor-shape metadata and storage leases | Core and a caller/host-supplied allocator; no mandatory tracing collector |
| **Application** | Managed list/linked list/dictionary/set/queue, ordinary managed `Text`, tasks, streams/terminal, files/network, globalization and serialization | Foundation plus tracing and appropriate host services |
| **Platform leaves** | COM/Windows/DirectX and other native bindings | Only layers their adapters actually use; no reverse dependency on platform APIs |

These are three coherent cumulative layers, **not** a feature-profile matrix for each allocator, SIMD width, encoding or collection. Namespaces describe functionality; referencing `Terrum.Collections` does not link every package or grant effects. An Application program can use Core's nonallocating kernels. Core does not promise that *all* error paths or callbacks allocate nothing; freestanding no-allocation execution additionally needs a compatible failure runtime. The initial CLR backend remains hosted even for Core-only consumers. Optional hardware acceleration may use compatible software paths; a hardware-scalable register type with a target ABI is not secretly software-emulated as another type. Modules publish normalized public contracts, effects, lifetimes, generic witnesses and ABI obligations independently of linkage choice. Pinning an implementation does not expand `internal`/`private` access. Contract-bound replacement and AOT require actual metadata/binder support, not merely equal method names.

The API inventories deliberately mix signatures with selected algorithm bodies. Unspecified bodies do not imply native exports or implementations. `[Copy]`, `[Sized]`, `[ManagedStorable]`, `[SimdElement]` and `[TextCodeUnit]` denote checked capability predicates rather than arbitrary user attributes. The [Foundation ownership inventory](../library/foundation.api.terrum) distinguishes a per-allocation **storage-and-release lease** from an owned **allocator context** retained by a growing vector. `Buffer<T>.Adopt` takes an existing allocation, validating byte extent, actual element alignment and required tracing capabilities; it does not create storage from a release token. Initial `Vector<T>` accepts `[Copy]` elements: `Reserve` obtains a new lease from its retained context, copies the initialized prefix, cleans partial copies on failure and publishes replacement storage only after success. The old allocation cannot be replaced while views borrow it. Affine/borrowed element storage, initialized prefixes, allocator-provider selection, write-guard enforcement and native GC barriers still need complete contracts. Additional proposed signatures and associated-family notation require language design and validation before they can become compiler acceptance fixtures.

## Scalar mathematics, keys and conversion

The granular `IAdditionOperators<TSelf, TOther, TResult>` and `IMultiplyOperators<...>` protocols in [numerics](../library/numerics.api.terrum) express an operand and a *possibly different* result. `IAdditiveIdentity<TSelf, TResult>` supplies an operation's zero. `IScalarNumber<TSelf>` composes selected closed scalar operations; IEEE classification/functions live on `IScalarIeee754<TSelf>`. `ISimdVector<TVector, TElement, TMask>` **inherits the same `IAdditionOperators<TVector, TVector, TVector>` witness**, not a second SIMD-only addition method. Vector, complex and matrix algorithms request only the operations they actually need. In particular, a SIMD vector does **not** become a scalar number by providing `+` and `*`. The inventory is representative; it does not implement the complete arithmetic or numeric-literal surface.

Integer arithmetic is checked regardless of build; wrapping/saturating/try forms are named. No promotion between already typed numbers is implicit. Numeric literals require an unambiguous context or tag. Conversion (`ConvertChecked`, `ConvertSaturating`, `ConvertTruncating`) changes numeric format and handles range/rounding; `Splat`/broadcast replicates the *same* lane value or tensor elements, without itself converting them. A widening vector conversion must define output shape and lane count explicitly -- it cannot silently discard half the elements. Fixed-width `float32` math has strict target-format rounding and no implicit reassociation/contraction; `FusedMultiplyAdd`, native/approximate functions and reproducible reductions are separate contracts. IEEE `decimal32` is not CLR `decimal` or a binary64 intermediary. The CLR's decimal BID software implementation is a useful reference, not proof of matching Terrum ABI, parsing, rounding and exceptional behavior.

`IParsable<TSelf>.TryParse` and `IFormattable.TryFormat<TWriter>` also serve user types. Core parsing/formatting is ordinal plus invariant: ASCII signs/digits/punctuation, whole-input parse, no locale, normalization or Unicode lookalike substitution. On false, `out` remains uninitialized. Formatting writes through the supplied typed writer, never a required intermediate `Text`. The default typed hook forwards to the value formatter; a custom handler can intercept values and forward nested typed parts. Refusal stops further writes without replay and can leave already accepted fragments. The supplied [numeric sketch](../library/numerics.api.terrum) retains the typed writer forwarding point.

Floating `==` follows IEEE (NaN unequal, signed zero equal). A **separate numeric-key comparer** makes all NaNs mutually key-equal, zeros equal and hashes consistent. Decimal key hashing must normalize numerically equal *cohorts* (`1.0`/`1.00`), not hash its raw encoding; signed zero and NaN also need canonical key hashes. A bitwise-identity comparer is different again. Maps/sets accept a paired equality/hash policy (`IKeyComparer<T>` in the [algorithm inventory](../library/algorithms.api.terrum)); `IndexOf` under ordinary operator equality must not silently adopt numeric-key semantics. Ordering and `Min` variants explicitly select NaN propagation and signed-zero policies. The runtime's distinct decimal `operator ==`, `Equals`, and cohort-normalizing hash illustrate why one implicit universal equality is insufficient ([source notes](references.md)).

## SIMD as a family of shapes

Explicit `simd64/128/256/512<T>` are fixed ABI shapes where supported; `simd<T>` denotes a **genuine target-scalable** type, not a preferred-width fixed vector. The [SIMD contract inventory](../library/simd.api.terrum) sketches a statically constrained vector/element/mask triple. The vector addition result is `TVector`, whereas lane comparisons return `TMask`, reductions may return `TElement`, and whole-vector equality returns `bool`; none implies the others. A mask represents **boolean lane predicates**, distinct from `bool` for whole-vector equality and distinct from a numeric data vector of all-one bit patterns. `CompareEqual` produces a mask; `Any`/`All` reduce it to a `bool`; `Select` consumes it. Mask shape and granularity must match vector element shape. Bit reinterpretation, numeric conversion, splatting, and rebinding vector families are distinct operations. Associated-family syntax and its higher-kinded/type-witness rules remain open; the sketch's three generic parameters are explanatory, not a required final spelling.

Fixed SIMD values can be `[Sized]` if layout supports their element type. The proposed initial scalable profile is SVE-like **sizeless**: locals, scoped loans and statically specialized compatible calls, but not ordinary fields, heap boxes, array/pool elements or aggregate payloads. [Arm ACLE](references.md#other-official-library-specific-prior-art) specifies related SVE vector/predicate restrictions, but does not supply Terrum's ABI or lifetime rules. Such live values cannot cross `await`, incompatible vector contexts or an ABI boundary that cannot carry them. RVV requires its own validated profile; mask representation, vector length and ABI cannot be copied blindly from SVE. Library dispatch checks CPU *and OS* support and selects concrete implementation variants before calling a scalable kernel. AOT publishes a bounded explicit variant plan rather than inventing runtime code generation. Reusable static operators/witnesses allow code sharing without erasing masks, boxing sizeless values or conflating vectors with scalar `INumber`.

Tail handling is part of correctness: `First(remaining)` masks the final iteration, inactive masked **loads/stores do not access memory**, and no safe lane is poison/undefined. Stores with repeated scatter indexes preflight active bounds before writes, then define duplicate-index order (last active lane wins). Aliasing/alignment rules are checked at the public boundary. A fixed vector may use full-vector processing and a scalar tail instead; neither strategy may read beyond the provided span. Dot/sum ordering across vector widths needs an explicitly chosen reproducibility policy: per-vector lane order alone is insufficient to make a whole-input reduction bitwise stable. Strict scalar order is a defensible default; a separately named relaxed/high-throughput reduction may regroup and document architecture-dependent results.

## Views, shapes and tensor primitives

One `Span<T>` family carries qualified read/write authority and opaque backing dependencies, **not** an owner generic parameter. `Span<T>` implements `IContiguousSequence<T>.AsSpan()` *explicitly* so a constrained generic caller can obtain a read projection without boxing, while `span.AsSpan()` is intentionally absent on concrete spans. Its implementation **forwards existing backing dependencies**, without borrowing the descriptor place simply because it read the descriptor. The broad interface receiver-view contract permits implementations to borrow receiver storage. A generic caller sees that broad contract; propagation of an implementation's narrower backing-only relationship through a wrapper requires a future **checked conditional member refinement**, published in the witness and validated/versioned. It is not inferred from a current body or resolved with a second `IScopedSequence` interface. Neither the broad nor narrowed rule extends owner/allocation lifetime or bypasses disposal. `TextSpan<TCodeUnit>.AsSpan()` remains public and drops text validity only, preserving immutable backing; erased `TextSpan` projects a code-unit span conditionally without transcoding.

[`TensorShape` and `TensorSpan<T>`](../library/tensors.api.terrum) express a *logical* rank-dynamic view, not a second owner family. Rank and dimension lengths are `nuint`; element strides are signed `nint` to allow reversed/transposed views. Rank-zero `[]` is a scalar with one element, while `[0, n]` is empty with zero elements; a default/empty sentinel must have an explicit shape rather than ambiguously representing both. Validate **every** dimension length as representable within the address/offset range, independently of order. Then `ElementCount` is zero if **any** dimension is zero; do not multiply the remaining nonzero dimensions of an empty shape. Otherwise calculate their checked product (rank zero has the multiplicative identity, one). For nonempty views, `origin + Σ(index[i] × stride[i])` uses checked signed arithmetic; derive minimum and maximum reachable offset using `(length[i]-1) × stride[i]` with checked operations and validate *both* against backing bounds. For zero-element views **skip all `(length-1)` address arithmetic and dereference**; their origin may be an in-bounds end location, and metadata/owner dependencies remain valid. `nuint` lengths cannot be casually cast to signed offsets; reject nonempty shapes outside representable address/element ranges. Width, alignment and shape-data lifetime are not inferred from a pointer alone.

Small shape metadata can be inline; arbitrary rank may use independent, immutable Foundation-owned metadata or explicitly borrowed metadata. A tensor view then has **two** dependency sources: data backing/access *and* externally stored shape metadata. Returning/storing/erasing it preserves both, even at an empty/end slice. The exact multi-source declaration/anchor ABI is unresolved; the sketch intentionally does not claim that the current `[ViewOf]` spelling proves the view factory. The `View(mut Span<T>, ...)` factory **returns `mut TensorSpan<T>`**; a read-only source returns a read-only view, never an upgraded writable one. Writable tensors require injective logical-index-to-address mapping (zero-stride broadcasting with length greater than one is read-only); overlapping or duplicate addresses cannot manufacture multiple writable loans. Broadcasting is a read view or an explicit materialization, not an implicit arithmetic conversion. `TryAsDenseSpan` succeeds only when the logical order actually maps to one contiguous range with proper access/lifetimes. An arbitrary transposition must not pretend to be contiguous. `CopyTo` checks equal logical shapes and `[Copy]` elements, traverses logical indexes, accepts disjoint backings or **identical per-index mappings** (no-op), and rejects displaced or differently strided overlap before writing; it does not allocate a hidden temporary.

Core `TensorPrimitives` operate over borrowed spans and caller destinations, not hidden owning tensors. `Add` requires compatible lengths/shapes and preflights destination capacity and alias safety before mutation. `Add`, `Sum`, `Dot` and copying tensor views explicitly require `[Copy]` complete elements when invoking value-taking operators; arithmetic witnesses alone confer **no** copy permission. A future operator consuming `ref T` would need a separate contract, not implicit duplication. Exact same-position in-place operands are permitted only where each output reads all required inputs before overwriting; displaced overlap is rejected unless an operation explicitly supplies memmove/temporary semantics. Numeric callbacks can still throw mid-operation, so an algorithm without a no-throw bound does not promise transactional output. `Sum(empty)` returns additive identity, `Dot(empty,empty)` returns zero; unequal dot lengths fail. A strict reduction observes logical row-major order and specified floating behavior; accelerated relaxed variants can specify different rounding/order. Fused operations avoid an intermediate allocation, but must not silently change IEEE rounding to FMA. Transcendentals, normalization and softmax require separate domain, overflow, NaN and stability policies; the runtime `SoftMax` span implementation uses exp-then-sum-then-divide, illustrating a cost/overflow tradeoff, not a Terrum semantic mandate.

## Collections, algorithms and application services

Foundation owns explicit `Buffer<T>`, `Vector<T>`, arena-backed storage, maps and persistent shape metadata with allocator/lease obligations; Application provides managed aliasable collections. The [managed collection inventory](../library/collections.api.terrum) specifies initial `List<T>` element restrictions (`[ManagedStorable]`, `[Copy]`, `[Sized]`); this is **not** a permanent language ban on storing pointers/loans or affine elements. GC visits only initialized slots and uses write barriers; no fabricated `default(T)` fills unused capacity. Preflight capacity, checked count/version and guard conflicts precede mutation; remove/clear vacate slots and release retained references. `ListWriteAccess<T>` lends checked exclusive access, keeps actual storage stable and live and releases once. Every alias, indexer, cursor and reentrant callback checks the relevant guard. It is not a cross-thread mutex. `TryGet` distinguishes missing index from a present optional/null element.

`LinkedListNode<T>` has stable **logical node identity**, not a promised machine address. Detached nodes remain usable and may be reinserted; attached nodes retain exactly one owner. Removal clears owner/links. `Clear` detaches *all* nodes, including externally retained nodes, and cannot merely drop the head/tail. Node values are accessors, never public writable fields that bypass guards. Membership/count/version are checked before nonthrowing link changes. A concrete `foreach` cursor need not box; structural mutation invalidates it, while payload replacement alone is not structural. Copy-, borrow-, consume- and snapshot-yielding iteration are separate operations.

[`SpanAlgorithms`](../library/algorithms.api.terrum) illustrates constrained static/eager calls over contiguous views. A mapper/predicate/comparer supplied as a generic `ref` has its own checked effects/captures; no hidden boxing, closure, allocation, deferred iterator or `IEnumerable` materialization. `Select` validates output length and **rejects any source/destination overlap, including exact in-place**, before invoking callbacks. `Where` reserves capacity for the *upper bound* `source.Length` so a stateful predicate is invoked exactly once per element and returns the written length. It accepts disjoint storage or **same-start in-place compaction**, reading the `[Copy]` source element and completing its predicate before writing at an index no greater than the read index; displaced overlap is rejected before callbacks. Callback failure in either algorithm may leave an accepted output prefix. A smaller destination needs an explicitly incremental/status-returning API; a preflight callback counting pass would change effects. Other LINQ-like producers (grouping/joining, sorting, lazy iteration) specify storage or laziness separately. Raw code-unit algorithms do not silently become Unicode-aware, and equality/hash policies remain paired.

`IFormattable` forwards typed fragments to `ITextWriter`, including nested Point components; bounded `SpanTextWriter<TCodeUnit>` captures its destination exclusively, counts accepted code units and refuses whole fragments without modifying the destination for that fragment. Immutable `Text`/`TextSpan` cannot become writable via a read cast; creating text validates/freezes storage, potentially transferring exclusively owned backing. `Terminal.Write`/`WriteLine` target **standard output** by default; `output: TerminalOutput.Error` selects error and invalid selectors fail. Streaming writers can have externally visible partial writes. Async writes format once into operation-owned buffering, drain to completion and retain borrowed content only within the declared operation lifetime; no replay, silent stringify fallback or cancellation-as-cleanup. Application file/network/terminal controls and generated serialization registrations are separate from Core; platform bindings require explicit native ABI/ownership/encoding adapters.

## Open contract work

Associated vector/mask family syntax and valid element predicates; scalable ABI/vector-context rules; exact anchored view and multi-source shape representation; checked conditional member refinement through generic wrappers; `TensorShape` zero-dimensional/default layout and signed-stride support; fast versus reproducible reduction naming; allocator selection; complete text storage/handler and async/backpressure contracts; collection storage capabilities beyond `[Copy]`; and language parser/type checker support for these inventories remain staged. Resolve and test these before treating a design sample as executable or claiming interface/module replacement compatibility.
